# 测试策略

## 测试落位

自动化验收测试优先放在 `app`（宿主）中，以 SDK 公共 API 驱动真实采集链路，模拟上层接入场景。SDK 模块内部如需独立契约验证，可在对应模块补充单元测试；不作为宿主场景测试的前置条件。

## 单元测试

不依赖真实等待或 Android 设备，优先覆盖：

- 小于阈值不生成事件。
- 等于或超过阈值生成事件。
- 事件序列化和反序列化保持字段语义。
- 并发写入不丢事件或损坏文件。
- 损坏 JSON 被跳过，不阻塞初始化和其他事件读取。
- 超过文件数量或总大小上限时清理旧事件。
- start、stop、重复初始化行为稳定。

测试应注入时钟、堆栈采样器和 `EventStore`，避免 `Thread.sleep` 造成不稳定。

## Android 测试

使用模拟器或真实设备验证：

- 主线程阻塞超过 700ms 能生成 `FreezeEvent`。
- 页面上下文能进入事件。
- 进程重启后能读取应用私有目录中的事件。
- 横竖屏切换不会持有旧 Activity。

## 性能验证

Release 构建下记录：

- 初始化耗时。
- 正常运行 CPU 和内存变化。
- 事件写入磁盘大小。
- 采样期间的额外线程数量。

## 证据要求

每次开发汇报必须说明执行了哪些检查、结果是什么、哪些检查未执行以及原因。没有运行测试时，不得写“测试通过”。
