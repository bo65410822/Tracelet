# Tracelet MVP 规格

## 版本目标

MVP 版本聚焦“主线程卡顿诊断”闭环：采集、归因、持久化、报告和验证。默认离线运行，暂不依赖服务器。

## 必须支持

### 卡顿检测

- 监控主线程消息处理延迟。
- 支持可配置卡顿阈值，默认 700ms。
- 记录发生时间、进程、线程和当前页面标识。
- 卡顿期间采样主线程堆栈，并限制采样数量和单事件大小。
- 同一堆栈在报告中可聚合，避免重复噪声。

### 启动与页面

- 记录冷启动和热启动耗时。
- 支持手动标记页面进入、首帧和加载完成。
- 提供 Activity/Fragment 的默认页面标识。
- 为 Compose 预留页面标识 API。

### 本地报告

- 事件以版本化 JSON 格式保存到应用私有目录。
- 支持按时间、事件类型和页面读取。
- 能导出单个报告供开发者查看或提交 Issue。
- 存储有文件数量、总大小和过期清理上限。

### 接入与兼容

- Kotlin API，同时保证 Java 可调用。
- 一次初始化，可配置启停和采样策略。
- 支持 Android API 24+、R8 和多进程配置说明。
- 诊断失败不得影响宿主应用主流程。

## 初步 API 形态

```kotlin
Tracelet.initialize(context) {
    freezeThresholdMs = 700
    enableStartup = true
    reportDirectory = context.filesDir
}

Tracelet.page("Home") {
    // 页面加载逻辑
}
```

API 在实现阶段可以调整，事件模型和低开销约束优先于保持示例不变。

## 验收标准

1. 人为阻塞主线程超过阈值时，生成一个 `FreezeEvent`。
2. 事件包含时间、页面和至少一份有效主线程堆栈样本。
3. 应用正常运行时无额外常驻采样线程，或线程数量符合性能预算。
4. 报告进程重启后仍可读取，损坏文件不会阻塞初始化。
5. 单元测试覆盖阈值、并发写入、过期清理和事件序列化。
6. Benchmark 给出 Release 构建下的 CPU、内存和磁盘开销。
7. 示例应用覆盖 Kotlin、Compose 和横竖屏切换场景。

## 明确排除

MVP 不包含云端上报、自动内存泄漏分析、网络链路追踪、字节码插桩、Native 崩溃解析和完整后台控制台。这些能力进入后续版本前，必须先验证核心事件模型是否足够稳定。
