# Tracelet 项目愿景

## 一句话定位

Tracelet 是一个轻量、低侵入、以本地分析为核心的 Android 性能与稳定性诊断工具包，帮助开发者在真实设备上回答：应用哪里变慢了、为什么变慢、如何复现。

## 要解决的问题

Android 应用的卡顿、启动变慢、页面加载异常和内存问题，往往只能通过零散日志猜测。Tracelet 将运行时信号统一采集为可关联的事件，并在设备本地生成可读报告，降低定位问题所需的上下文成本。

## 核心原则

- **Android first**：优先利用 Android Framework、ART、Choreographer 和 Compose 的原生能力。
- **低开销**：诊断工具不能成为被诊断应用的性能问题。
- **本地优先**：默认不联网、不上传业务数据，先在设备上完成采集和分析。
- **低侵入**：业务只需一次初始化，避免强制修改业务代码和生命周期。
- **可扩展**：卡顿、启动、页面、内存和网络能力共享统一事件模型。
- **可验证**：每项能力都配套 Benchmark、示例和可复现案例。
- **确定性优先**：只采集具有明确系统信号、稳定语义且可重复验证的指标；不通过启发式方法猜测网络完成、业务内容就绪或其他宿主状态。

## 目标用户

第一阶段面向个人开发者和 Android 团队，用于开发调试、性能回归和线上问题复现。Tracelet 暂不以完整云端监控平台为目标。

## 暂不做的事情

- 不建设自有云端数据平台、账号和权限系统。
- 不默认采集或上传用户业务数据。
- 不追求一次覆盖所有厂商 ROM 和所有 Android API。
- 不在 MVP 阶段实现完整崩溃收集、风控或 APM 平台。
- 不为了功能数量牺牲 SDK 的稳定性和可测量开销。

## 成功标准

Tracelet 的第一阶段成功，不是功能最多，而是开发者可以在一个 Demo 中稳定复现卡顿，并通过本地报告定位到页面、时间和主线程堆栈；同时 Release 包中的常规运行开销可被 Benchmark 证明在预算内。
